# review_pack

`tools/review_pack.py [-C DIR] <branch> [--base BRANCH] [--diff PATH]` prints, read-only, what a reviewer or lander needs about a branch. Logic: `kitlib/reviewpack`; the trailers rule is `kitlib/reviewpack/trailers.py`.
- `--base` defaults to gate.md "Default base" (`<remote>/<main>` when it resolves, with a line when the local main differs). `--diff PATH` prints only that file's diff against the merge-base.
- Files are grouped by the risk level in `docs/ops/risk-map.md` (unlisted = High, except a `.md` file: Low). `risk_rules()` reads each `- Level ... | paths` line; a path is a plain path prefix (`net/`, `project.godot`; matched from the repo root only) or a glob: `*`/`?` within one segment, `**` across segments, `{a,b}` choices (`ui/*.gdshader`, `**/*.tscn`); a glob with no `/` (`*.gdshader`) matches at any depth. `level()`: the longest matching plain prefix decides, and a matching glob can only raise that result; with no plain match the most specific glob (the longest literal text) decides; equally specific rules resolve to the higher level, and a glob's literal text is its letters and digits, and a rule with none (`**`, `**/*`, `*.*`) is ignored. A token that starts with `**` not followed by `/` is bold markup, so `**docs/**` reads as the prefix `docs`. A `?` right after a path in the map text is read as prose, not a wildcard.
- Owner-only paths and the trailer key come from `owner_rules()`: the base's `owner` section merged with the branch's (`kitlib.config.owner.merge`). As the landing guard judges (guard.md "Owner-only commits"), a commit whose author is the base's "owner".email is OK with or without a trailer (the author read by `ownercommits.commits`, judged by `is_owner`); its row shows an Owner-Approved trailer that covers the path. On anyone else's commit that trailer approves nothing. `Owner-Approval: hub:A-<n>` on a non-merge commit reads ok by its form only; landing verifies it with the hub.
- `.kit.json` "review_pack".coauthor (a switch, read at the base) adds a section of commits with no Co-Authored-By trailer. `Owner-Approved` or `Owner-Authored: yes` excuses one only when `is_owner(author)`; otherwise it is printed as an unproven claim and the commit FAILs. With "owner".email unset nothing is the owner's.
- The doc budget runs as `<python> <kit>/tools/doc_budget.py -C <checkout> --base <base> --head <branch>`, judged by `kitlib.verdict`. A kit without that file prints `docs NOT CHECKED` and does not change the exit status.
- The doc index check runs as `<python> <kit>/tools/doc_index.py -C <checkout> --head <branch>` (`kitlib.reviewpack.index_line`), printed as a `doc index` line and judged on `DOC INDEX OK` / `DOC INDEX FAILED`; a failure is exit 1. The base's `.kit.json` "doc_index".enabled false prints nothing.
- The `gate` line (`kitlib.reviewpack.gate_line`, after the commits) says whether the branch tip has a gate-OK record for exactly that commit from a `gate.py --full` pass (`gate_ok.verify_full`): `gate     tip <sha>: full gate OK, ended <time>`, `gate     tip <sha>: NO full-gate OK record (<why>); landing will refuse`, or, when the branch tip cannot be resolved, `gate     tip of <branch> cannot be read (<why>); landing will refuse` (gate.md "Landing"). It is printed only and never changes the exit status.
- Exit codes: 0 nothing blocks, 1 an owner-only problem, a failing commit, a failing doc budget or a failing doc index listing, 2 usage (including a `-C` that is a drive and colon with no separator, `Z:GitHub...`, whose backslashes the shell ate: the message names the forward-slash form), no merge-base, a failed git read or the configuration. A merge-base failure names git's exit and first stderr line; with exit 1 and nothing on stderr in a shallow clone (`merge_base()` asks `git rev-parse --is-shallow-repository`) it adds that the clone may lack the shared commit. `--diff` prints no base note, except in brackets after a merge-base failure.

Tests: `tests/reviewpack`.
