# Worktree remove

Remove a workstream's worktree only when its work has landed and nothing holds it, abandon unlanded work under a tag, and sweep landed idle worktrees nightly. Ported from the PM kit's `tools/worktree_remove.py` and `tools/worktree_sweep_task.py`. On Windows `git worktree remove` destroys the worktree's registration when it fails partway, so every check runs before git is called.

## Tools

- `tools/worktree_remove.py [-C DIR] <path or slug> [--keep-branch]`: check, remove, then `git branch -d` (never `-D`).
- `... <path or slug> --abandon "<why>" [--keep-branch]`: for UNLANDED work. Tags the tip `archive/<slug>`, then removes the tree and the branch.
  - A LANDED tree that holds uncommitted or untracked work (the plain verb refuses it) is abandoned too (`kitlib.worktree.remove._abandon_landed_dirty`; before, the plain verb and `--abandon` each refused it and named the other). The plain verb's checks run first. Then the work, tracked changes and untracked files that are not ignored, is saved as a commit on the tip, written through a throwaway index (`snapshot_tree`), under the annotated tag `archive/<slug>`. The line is `saved     uncommitted work (<n>) of <path> as <commit> under tag archive/<slug> ...`, with the `git diff` that shows it. The tree is read again and must still match the saved commit, with HEAD unmoved. Then it is reset to its HEAD (`git reset --hard`, `git clean -d`, never `-x`), removed through `git_remove`, and the branch goes with `git branch -d`. A rerun reuses a tag that already holds exactly this work on this tip. A tag on anything else refuses, nothing changed. A file written between that last match and the reset is lost: the window is narrowed, not closed. A landed, clean tree is still refused (`nothing to abandon`).
- Both verbs also take, by its PATH only, a registered DETACHED worktree outside every worktree folder (an agent's red-run tree): the same checks, then removed with no branch to delete; `--abandon` tags its HEAD `archive/<folder name>`. Refused, nothing changed: the main checkout, a path inside it or holding it, a link or junction on the way (the path and each folder above it, checked one by one with `holders.linked`, so an 8.3 short name or another spelling of the same folders is the same tree, not a link: `link_on_the_way`), an exempt folder, an unregistered folder, a tree holding another registered worktree, a locked tree, a tree on a branch (a workstream's, under the worktree folder) and no HEAD; a missing folder is `nothing` (exit 0) (`kitlib.worktree.remove.outside_target`). A relative path is taken against the caller's directory.
  - Its HEAD reflog (`<git dir>/logs/HEAD`) and per-worktree refs, all deleted with the tree, are checked before any git write, as `--scratch` checks them (`kept_reflog`, with `kitlib.worktree.scratch` `reflog` and `reachable`): a commit no ref reaches is the owner's call, never this tool's. The plain verb refuses when HEAD or any of those commits is in no branch, remote-tracking branch or tag (`which no ref reaches`), even when HEAD itself is in the base. `--abandon` refuses too, naming each such commit that the tag on HEAD would not keep either; it tags nothing. A reflog or ref list that cannot be read, or a reach that cannot be told, refuses. The HEAD held to all this is the one the merge check found in the base (`merge_check`'s `seen`), and just before `git worktree remove` both verbs read HEAD, the reflog and the per-worktree refs again (`scratch.unmoved`) and refuse when any moved (`HEAD moved after it was checked`, `its HEAD reflog or a per-worktree ref changed after it was checked`).
  - A SLUG never names such a tree: with no folder under the worktree folder but an outside tree of that name, it is refused (exit 1) with each path-form command (`slug_redirect`): `"<path>" --scratch`, `"<path>"` and `"<path>" --abandon "<why>"`. For an agent's red-run tree under a temp folder use `--scratch`: it needs only HEAD and the reflog in some ref, and it restores uncommitted files git already holds, where the plain verb needs HEAD in the base and refuses any uncommitted file. The plain verb is for a tree whose HEAD has landed, `--abandon` for unlanded work worth a tag. A worktree list that cannot be read for a missing slug is still `nothing` (exit 0), after a `note` line saying an outside tree of that name could not be looked for.
  - Printed reruns name an outside tree by its quoted path (`handle`). The landing cleanup (`kitlib/gate/cleanup.py`) is unchanged: it removes a landed branch's tree, and an outside tree on a branch is refused.
- `.kit.json` `worktree_remove.branch_template` is one `{slug}` template or a list of them (`phase/{slug}` plus `records/{slug}`): a slug-form removal is refused unless the worktree is on the branch one entry makes from its folder name (the refusal lists every candidate). An empty list, a non-string entry or an entry without exactly one `{slug}` is a configuration error (exit 2), never an allow.
- `... <branch> --branch`: a LANDED local branch with no worktree, deleted with `git branch -d` (never `-D`). Refused, with nothing changed: the main branch, a branch any worktree has checked out (use the slug form), a tip not in `<remote>/<main_branch>` as it stands (the refusal names `--branch --abandon`), and a backlog record still pulled by the branch (an open claim, as the sweep reads it). A missing branch is `nothing` (exit 0). The remote branch is not touched.
- `... <branch> --branch --abandon "<why>"`: for an UNLANDED local branch with no worktree. Tags the tip `archive/<name>` (`<name>` is the branch with the prefix and suffix of the first `branch_template` entry it fits cut off, else the whole branch name), then deletes the branch with `git update-ref -d` held to the tagged tip. Refuses the main branch, a missing branch, a branch any worktree has checked out (use the slug form), and a branch already in the pushed base (the refusal names `<branch> --branch`, or the landing cleanup `land.py --sweep-landed`). The remote branch is not touched, as in `--abandon`. `--keep-branch` is a usage error here.
- Both `--branch` forms take the name exactly: one `git check-ref-format --branch` does not echo back (`main~1`, `main^`, `main@{1}`, `@{-1}`) or one differing from a branch only in case (`Main`) is refused, and the main-branch and checked-out checks ignore case (`kitlib.worktree.remove.local_branch`).
- `... <path> --scratch`: a SCRATCH worktree, a detached tree an agent made under its temp folder (red evidence against an older commit). It takes exactly one path and no other option. It removes the tree only when every one of these holds (`kitlib.worktree.scratch`):
  - The path is under a scratch root: `AGENT_TEMP`, `TEMP`, `TMP` or the shared temp folder (`kitlib.config.user.shared_temp`), read from the environment. A root that is not an existing absolute folder, is reached through a link, or is a drive root, the home folder or above it, or holds the main checkout is no root. A path inside the main checkout or a worktree folder (`homes_of`, junctions resolved) is a workstream worktree: use the slug form. The roots come from the caller's environment, so they are a scope hint, not protection: the reachability and content checks below are what protect the tree.
  - No link or junction is on the way. The tree is registered, not locked, detached, and holds no other registered worktree. Its HEAD, every commit in its HEAD reflog (`<git dir>/logs/HEAD`, deleted with the tree) and the tip of each of its per-worktree refs (`refs/worktree`, `refs/bisect`, `refs/rewritten`, deleted with it too; one that is not a commit refuses: `scratch.reflog`) are in a branch, remote-tracking branch or tag; a commit no ref reaches is the owner's call, never this tool's. A ref that does not peel to a commit is skipped, and a failed `merge-base` proves nothing: it refuses only when no other ref proves the commit reachable.
  - Nothing holds it, no link is inside it, and its ignored files are build output only (the rules above).
  - Every uncommitted file, and its staged blob, equals `<ref>:<path>` for some ref under `refs/heads` or `refs/remotes`: the same path only. A rename, copy, conflict, type change, quoted path or nested repository is refused.
  - It then checks each file once more, resets the index, checks tracked files out of HEAD (`GIT_LITERAL_PATHSPECS=1`), deletes untracked ones, each re-hashed with no link on its way just before (`restored  N file(s) found in git at their paths`), reads HEAD, the reflog and the per-worktree refs again (`HEAD moved after it was checked`, `its HEAD reflog or a per-worktree ref changed after it was checked`) and removes the tree through `git_remove` (see "The last status read"), never with `--force`. A status, worktree list, reflog or hash that cannot be read refuses. An unregistered folder is never deleted (`refused ... not a registered worktree`), and a missing one is `nothing` (exit 0). A file rewritten after its check is kept: `changed after it was checked`. The window from that check to git is narrowed, not closed. So is the one from the last HEAD and reflog read to `git worktree remove`: a commit made inside it is removed with the tree. The reflog is read from `logs/HEAD`, so a repository whose ref format is not `files` (reftable) is refused.
  - To make red evidence without leaving such a tree, use `tools/redfirst.py` (docs/redfirst.md).
- `... --check`: lists stumps and orphans (exit 1 if any) and, for information, landed worktrees.
- `... --sweep-merged [--apply]`: the nightly sweep. Without `--apply` it is a dry run. It refuses anywhere but the main checkout.
- `... --classify [--json]`: read-only. Sorts every registered worktree but the main checkout into one class (A, B, C, E or L; see "Classify"). `--json` prints the data instead of the lines. It takes no other flag but `--apply`, which removes the A and E trees (see "Classify").
- `tools/worktree_sweep_task.py [-C <main checkout>] [--register --owner-confirmed]`: prints the scheduled-task line. With both flags it runs it in PowerShell. A bare `--register` is refused, and agents never type `--owner-confirmed`.

Exit codes: 0 done, 1 refused or failed (or the sweep deferred, or `--classify` found a tree in A, B, C or E), 2 usage or a refused `.kit.json`, 130 Ctrl+C.

## Classify

`kitlib/worktree/classify.py` `classify` without `--apply` deletes, moves, fetches and writes nothing. Every git call is a read, and the status is read with `--no-optional-locks`. The base (`origin/main`) is read as it stands and never fetched, so the header says `(as it stands, not fetched)`. The backlog store is opened with `fetch=False`. Each tree gets the first class that matches, in this order:

| Class | Rule | Next step the output names |
|---|---|---|
| L live or kept | Locked with `git worktree lock`; exempt; the landing tree (`_landing`); its folder missing; or held. Held means one of: the landing lock names its branch; a machine lock record names it (`sweep.machine_lock_holder`); a process has its current directory in it; or its last activity is newer than the dead bar. A tree whose status or last activity cannot be read is L too. | reported only |
| A landed | The tip is in the base and off its first-parent chain (`merged_worktrees`' rule), the tree is clean, and a tree on a branch has a commit of its own in the branch's reflog (`own_commit`). | `worktree_remove.py <slug>` |
| E evidence | The folder name matches `EVIDENCE_GLOBS` (`agent-*`, `*-red`, `redcheck`, `mutant*`), or a detached tree outside every worktree folder. | `--scratch` or `--abandon "evidence"` |
| B finished | Clean, ahead of the base, and its tip has a `--full` gate-OK record git still agrees with (`gate_ok.verify_full`). | land it or record why not |
| C half-done | Anything else: dirty, no gate-OK record, a record that cannot be read, or no commit of its own. | take it up, or block or release its record; then `--abandon` |

- The dead bar is `DEAD_AFTER_S`, 24 h. Last activity is `sweep.last_activity` for a tree on a branch. For a detached tree it is the newest of: the tree, its git dir (the index left out) and the HEAD commit's date.
- A run-wide probe that cannot be read makes every tree L, and a `note` line says why. The run-wide probes are the landing lock, the machine lock and the process list. A process the scan cannot open (another user's, or a protected one) is counted on the `processes` line and not searched. When there is one, a tree no other rule holds is L unless every folder in it opens for delete (`holders.held_folder`: Windows refuses that open on a process's current directory), so L can also mean "a process we could not read may hold it"; a folder that refuses, a walk error or a tree past `WALK_MAX` entries makes it L. A git HEAD of forty zeros (an unborn or missing branch) is L. A tree on a branch is A only when the branch's reflog shows a commit made on it (`own_commit`): a branch made at a landed commit and never worked on is C (`nothing of its own`), and a reflog that is missing, expired or cannot be read is C. B's record must come from a `--full` gate (`gate_ok.verify_full`); a record from a gate without it shows as `gate: not full: ...` (C). The backlog's `block` and `release` of another branch's pull ask `branch_liveness`, the same L rule for the one tree on that branch (docs/backlog.md "Stopping a pull").
- Each tree's line shows the backlog records its branch pulled (`claim:`). This is shown only and never used to classify.
- Each B and C tree gets a `next` line with its `--abandon "<why>"` command. That line is for after the tree has been taken up or recorded.
- Exit codes: 0 when every tree is L, 1 when any tree is A, B, C or E (or a run-wide read failed: `failed ... nothing was classified`), 2 for a refused `.kit.json`.

`--classify --apply` (with or without `--json`) classifies as above, then removes each A and E tree through the existing remove paths (`apply_tree`): A by the plain verb; E by `--scratch` when it is detached under a scratch root and every commit its HEAD and HEAD reflog hold is reached by a ref (`scratch_route`), by the plain verb when its tip is in the base, else by `--abandon "evidence"` (tag `archive/<slug>`). An A tree, and an E tree that does not go to `--scratch`, is first checked the same way: when its HEAD reflog holds a commit no branch, remote-tracking branch or tag, and not its tip, reaches, it is `skipped` (`reflog holds unsaved commits`) and left for the owner (also when the reflog cannot be read), because the remove deletes that reflog, the tag holds only the tip, and the remove path checks the reflog only for a tree outside the worktree folders. Each path makes its own checks again, so a tree held, dirtied or moved since it was classified is refused there. B, C and L trees are never touched, nothing is fetched and no remote branch is touched.

- It runs on the main checkout only, as the sweep does. A held landing lock (`sweep.landing_hold`) refuses the run before anything is read: `refused   ...; nothing was classified or removed`. The lock is read again before each tree; taken mid-run, that tree and the rest are `skipped`. The machine lock is read again before each tree too (as the sweep does): a tree a record now names, or every tree while the lock cannot be read, is `skipped`.
- One line per A or E tree, `removed|failed|skipped <path>: <class>, <path taken>[, tag archive/<slug>]` and, for a failure, the path's first refusal. A tree whose worktree was removed but whose path then refused (its branch kept by `git branch -d`, say) is `failed`: `the worktree was removed, but <refusal>`. The B, C and L blocks, `next` lines and `summary` follow, then `applied   removed N, failed N, skipped N`. In `--json`, each such tree has `apply` (`result`, `why`, and the path's own `lines`) and the data has `applied`.
- Exit codes: 0 when every A and E tree was removed and no B or C tree is left; 1 when the run was refused, a tree failed or was skipped, or a B or C tree is left; 2 for usage or a refused `.kit.json`. `--apply` without `--classify` is still the sweep's (`--sweep-merged --apply`).

## The last status read

`kitlib.worktree.remove.git_remove` calls `last_look` first: one more read of `dirty`, just before `git worktree remove`. git's own refusal names modified and untracked files and never an ignored one, which it deletes with the tree, so this read is what keeps an ignored file written after the caller's own checks. Every removal goes through `git_remove`, so every caller gets it: the remove and abandon verbs (after `clear_disposable`), the sweep (after its second `sweep_status`), the landing cleanup (through `_remove`), `--scratch` (after `restore` and `clear_disposable`) and redfirst's cleanup (`kitlib/redfirst/run.py` `remove_tree`).

- It refuses on anything `dirty` lists: a modified or untracked file (one `disposable_untracked` names too: the verbs have cleared those by then), an ignored file outside `build_output`, a keeper inside it. The line is `failed    <path> changed after it was checked - <what>; git was NOT run`. A status that cannot be read gives `failed    <path>: its status could not be read again (<why>); git was NOT run`. The tree stays registered and intact, `--abandon` keeps its tag and the branch, and the sweep counts the worktree under `failed` (exit 1).
- A folder that vanishes between the caller's checks and `git_remove` is refused the same way: no status can be read where it was, so git is not run. Before `last_look`, `git worktree remove` dropped the entry of a missing folder and the branch went with it. Now the registration and the branch stay, and later runs report the entry: `--check` lists it as an `orphan`, the sweep skips it (`its directory is missing`), the landing cleanup (`kitlib/gate/cleanup.py` `clean_branch`) keeps it as `registered, and its folder is gone`, and the remove verb answers `nothing   <path> does not exist`.
- The window is narrowed, not closed. An ignored file written after `last_look` returns and before git deletes its folder is still deleted, without a word from git.
- `last_look` does not repeat the link check (`holders.link_reason`): a link or junction made inside build output after the verb's link check is not seen. One outside build output is refused when the status lists it or what it leads to (`??`, or `!!` when ignored).

Tests: `tests/worktree/test_remove_snapshot.py` (`IgnoredAfterTheLastStatusRead`; after `clear_disposable`, a tracked edit and delete in `FileAppearsInTheWindow`, a `disposable_untracked` file in `DisposableInTheWindow`, a junction in `JunctionAppearsInTheWindow`, a vanished folder in `FolderGoneInTheWindow`) and `tests/worktree/test_worktree_sweep.py` (`Sweep.test_an_ignored_file_written_after_the_sweeps_second_status_read_survives`).

## The scheduled task

`kitlib/worktree/task.py` `command` writes the one PowerShell line `tools/worktree_sweep_task.py` prints or, with `--register --owner-confirmed`, runs. The task `<repo name>-worktree-sweep` runs daily at 03:00 as the registering user (`-RunLevel Limited`, `-StartWhenAvailable`), its working directory the main checkout.

- No console window opens. The task's program is the `pythonw.exe` of the base install of the python that runs the tool (`sys.base_prefix`; `kitlib/launcher/pythonw.py` `base_pythonw`), named in the line itself (`PYTHONW_IS`), never a `Get-Command` lookup, which gives the `WindowsApps` alias when that folder is first on `PATH`, and its arguments are `"<kit>\tools\no_window.py" python "<kit>\tools\worktree_remove.py" -C "<main checkout>" --sweep-merged --apply` (`argument`). `tools/no_window.py` is the carrier (docs/daily-full.md "The schedule"): it starts the `python.exe` beside that `pythonw.exe` with a console that has no window and exits with the sweep's exit code.
- The tool refuses (exit 1, nothing printed or registered: `refused   ...; nothing was registered`) when that `pythonw.exe` is under a `WindowsApps` folder or is not a file (`kitlib/launcher/pythonw.py` `refusal`); the line itself still throws, registering nothing, when `$py` is empty or under `WindowsApps` (`NOT_THE_STORE_ALIAS`).
- The line does not replace a task: PowerShell refuses to register a name that exists. A task registered before the carrier runs `python` directly, with a window, until the owner removes it (`Unregister-ScheduledTask -TaskName '<repo name>-worktree-sweep' -Confirm:$false`) and registers it again.

## Behaves differently from the PM copy

- `-C` is a plain path option. There is no `checkout_guard` hand-off to the main checkout's copy, no `KIT_REPO_ROOT` and no `check_same_repo`; the kit has one copy. A relative path argument resolves against the process's own directory.
- Landing lock: read through `kitlib.records.landing.LandingLock` (`<common dir>/kit-landing.lock` unless `landing.lock_file` names another). There is always a place, so "no lock configured, defer" is gone. A file there that is no lock record counts as held.
- Open claim (sweep) and pulled warnings (abandon) read the backlog store backend: a record with `state: pulled` and `pulled_by: <branch>`. The PM copy grepped the base for any `pulled_by:` line. A `ref` or `branch` store is read at its local ref as it stands (not fetched, not per revision); an absent ref holds no records. A store that cannot be read skips the worktree (sweep) or prints a note (abandon).
- Machine lock: read through the kit's own `<kit>/tools/machine_lock.py status --json` only (the tool read beside the kit, `kitroot.lock_tool`). There is no `MACHINE_LOCK_TOOL` or `MACHINE_LOCK_TEST_ROOT`. Both the PM shape (`lock.held/waiting/background`) and the kit snapshot (`runs` plus `queue.entries`) are accepted; anything else defers the sweep.
- Sweep task: `-C` replaces `--repo`. The task runs this kit's `tools/worktree_remove.py` by absolute path with `-C <main checkout>`. The kit-stub check is replaced by a check that the tool sits in a main checkout (not a branch worktree's copy).
- `<branch> --branch` without `--abandon` is new: neither the PM tool nor any repo's own copy removed a landed branch without its worktree. Its checks are the plain verb's merge check and the sweep's open-claim check.
- Output is collected and printed when the verb ends, not streamed. The `--apply` log (`<shared temp>/<repo name>-worktree-sweep.log`) is written from the same lines.
