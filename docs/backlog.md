# backlog.py

The backlog's reads and writes: `tools/backlog.py` (entry) over `kitlib/backlog` (library). docs/backlog-store.md is the design; this page is the behaviour. Not live until reviewed.

## Stores

`.kit.json` `"backlog".store` picks the backend (kitlib/backlog/store.py `open_backend`):

| Value | Records live in |
|---|---|
| absent or `ref` | `backlog/<ID>.md` on `refs/backlog/main`, which shares no history with main |
| `branch` | the same tree on a `backlog` branch |
| `main` | `docs/backlog/<ID>.md` in the checkout; any other value is that folder |

A ref or branch write (`Store.write`) loops: fetch, plan against that snapshot, validate, build the tree in a temporary index, `commit-tree` on the fetched tip, then `push --force-with-lease=<ref>:<tip>`. With no remote it runs `update-ref <ref> <new> <tip>`. A lost race (including `cannot lock ref`, read from both of the push's output streams) reruns the whole attempt, plan included, up to `ATTEMPTS` (5); after that it is ERROR and nothing was written. A push that exits non-zero yet left the remote at or past the new commit (kitlib/git/refs.py `is_ancestor`) succeeded and is not re-planned; one rejected with the remote unmoved is ERROR. When the remote or the fetch that would tell cannot be read after a failed push, the ERROR says the write may have landed: read the store (`check` fetches it) before retrying (`RefBackend._maybe_landed`). Without a remote, an `update-ref` that fails or times out after the ref already moved to the new commit succeeded. After a push the local copy of the ref moves only as a fast-forward (`RefBackend._advance_cache`). A write is refused only for what it adds: a FAIL `check` would report (`check.fail_findings`), or an `item:` blocker naming no record (`check_change`), so a store that is already broken can still be repaired. Writes never touch the checkout. A fetching read adds the store's fetch refspec (`+refs/backlog/main:refs/backlog/main` for `ref`) to the remote once (`RefBackend.ensure_refspec`), and refuses when the remote has no store but the local ref holds one. The commit body carries `Session:` and, when the write cites one, `Ruling: PM R-nnnn`.

No remote means `git remote get-url <remote>` exits 2 and the repository lists no remote at all (`find_remote`); a missing remote beside others, or a lookup that fails any other way, is ERROR.

The `main` backend writes files. It has no compare-and-swap on the files: a write checks that each record it rewrites still holds the bytes it read, then writes. So it writes only in a linked worktree and refuses in a main checkout (`MainBackend.publish`). Outside the PM data branch's worktree it commits nothing (landing carries the files).

In the worktree that has the PM data branch checked out (`MainBackend.commit_branch`: kitlib/pmdata `read` names the branch and HEAD is that branch), each write commits its own record paths and nothing else (`MainBackend._commit`). The blobs are hashed before any file is written; a file that fails to write puts the others back and is ERROR. A temporary index then takes HEAD's tree plus those paths, `commit-tree` parents it on HEAD, and `update-ref HEAD <new> <old>` moves the branch, retried on a moved or locked HEAD up to `ATTEMPTS` (5). Every attempt, the first included, stops, ERROR and uncommitted (`errors.Overtaken`, an `Uncommitted`), when a commit changed any of the write's paths on HEAD since the write began: `MainBackend.publish` reads HEAD before it checks the files against what it read, and `MainBackend._publish_commit` compares the paths at that HEAD and at the one it builds on. So a write never commits over another session's commit of the same record that landed after `publish` read HEAD. A commit that landed before that read is not seen by the compare: only the files check stops it, when the file on disk differs from what the write read. The refused write then puts each file it wrote back (`MainBackend._put_back`): a path the other commit changed (`Overtaken.changed`) to what that HEAD holds, removing one HEAD lacks, so a read and the next write see the other commit's record; any other path of the write to the bytes it held before the write, a deleted file included, so a record that was uncommitted stays as it was and `catch-up` still lists it. Between the write and the put back a reader of the folder sees the refused content. It touches a file only while the file still holds exactly the bytes the write wrote, and fetches HEAD's content first so that no git call sits between that check and the write; the folder has no compare-and-swap, so a change to the file between the check and the write is still overwritten (a stated residual). The content goes in whole or not at all (`store._replace_file`: a file beside it, then `os.replace`), so a put back that fails leaves the file as the write wrote it, never a part. Any other file is left, the message names it with `git -C "<worktree>" diff HEAD -- "<path>"...` to compare first (`Overtaken.left`, `Overtaken.compare`), and it gives no ready-made `catch-up --apply` command. A write that read another session's file before that session committed it is refused the same way, though it would have overwritten nothing: that false refusal is accepted, and the write is repeated. When `publish` cannot read HEAD at all the ERROR says nothing was written. The real index then takes those paths only, so other staged or pending work is left as it was. A write that leaves the tree unchanged commits nothing. The commit message is the one a ref write uses (`Session:`, `Ruling:`). A commit that fails after the files are written is ERROR (`errors.Uncommitted`) naming the paths and `catch-up`. A commit that lands with the real index not updated is `errors.IndexStale`: HEAD has the commit, a plain `git commit` in that worktree would revert it, and the message gives the repair, `git -C "<worktree>" reset -q -- "<path>"...`. tools/backlog.py reports that write as written: the `WROTE` line (`CAUGHT UP` for `catch-up --apply`), then a `WARNING:` line carrying the message and the repair, exit 0 (`do_write`, `do_catch_up`). Every path in a printed command is in double quotes (`store.quoted`). These git calls drop an inherited `GIT_INDEX_FILE`, `GIT_DIR` and `GIT_WORK_TREE` (`store._store_env`), so a hook's environment never redirects them. Tests: `tests/backlog/test_pmdata_commit.py`.

## Commands

Globals: `-C DIR`, `--session S` (the offer and the commit body), `--as BRANCH` (pull or release as), `--no-fetch` (read the local copy).

| Verb | Does |
|---|---|
| `next [--cap N \| --all] [--with ID]...` | The banner, then up to N offers for `--session` (default 5, `offer.py` `DEFAULT_CAP`), then what was passed over and why. `--all` offers every startable record, uncapped, with the same pass-over lines (a scope collision still passes one over); it beside `--cap` is USAGE. A pull whose branch is gone prints `DEAD PULL ID ...`: a pull by the record's own `session:` takes it over, anyone else `release`s it first. Tests: `tests/backlog/test_next_all.py` |
| `show ID`, `list [--blocked [--on M]] [--needs-priority] [--status S] [--area A]` | Reads; `--needs-priority` is the open unpriced records, sorted by id; a parked row adds its `q` and days parked. `show` of a missing id is NOT FOUND (exit 1) plus the store commit that deleted its file (short sha, commit date, `Session:`, subject; no author name), found through merged side branches (`git log --full-history --no-renames --diff-filter=D`), or "the id is unknown". On a main store, where a write outside the PM data worktree commits nothing, a record whose file HEAD tracks and the worktree no longer holds says so (closed or retired here, or removed by hand; no commit names it yet), and a git that does not answer leaves the "history could not be read" line (store.py `MainBackend.uncommitted_removal`; `tests/backlog/test_show_history.py`). An id with a glob or path character is not looked up, and a history git cannot read still prints the plain NOT FOUND with a line saying so (kitlib/backlog/plan.py `require_shown`, store.py `last_removal`) |
| `check` | Schema, store and pull checks; no check reads the rulings ledger (below). RED exits 1 |
| `landable BRANCH...` | 0 LANDABLE, 1 CANNOT TELL, 2 NOT LANDABLE (it holds a pull) |
| `stale [--days N]` | Read-only, default 30 days. Lists records whose last store commit is N+ days old, backticked body paths with no file, and `files` entries changed or gone since `files_at`. A record a test could not judge is NOT CHECKED, never current; the SWEPT line counts skips. Age is the last commit that wrote the record: after `migrate` it is the migrate date until the next write, and an uncommitted `main`-store edit ages by its last commit |
| `add ID --summary S --scope P...` | One record, always `priority: -`; `--reopen` to reuse a closed id |
| `set ID --<field> V ... [--unset K] [--ruling R] [--body-file F]` | Edits fields; `--body-file F` replaces the whole body (an empty file is refused; the kit has no body-line keys, so no `edit-body`); `set ID --hold-ruling R` alone re-cites the hold ruling |
| `block ID --on M... [--owner-ask Q] [--reason T]`, `unblock ID [--on M] [--reason T] [--ruling R]` | `block` replaces `blocked_on`. `block --reason T` puts the reason in the commit subject (`backlog: block ID on M: T`) and appends one line to the record's body, `Blocked on M (date): T`, which `show` prints; no header key is written, and a reason under 12 characters is USAGE (`plan.py` `plan_block`; `tests/backlog/test_block_reason.py`). `unblock` clears one blocker: a lone one opens the record (`--on`, `--reason` optional); with several, `--on M --reason T` removes M only and the record stays blocked on the rest, and a bare `unblock` is REFUSED with the blockers and the command for each. The reason goes into the commit subject (`backlog: unblock ID from M: T`). Clearing `owner` needs `--ruling`. Tests: `tests/backlog/test_unblock_one.py` |
| `pull ID [--reason T] [--ruling R]`, `release ID --reason T` | Written at once; `pull` records the branch; outside the offer it needs `--reason` |
| `close ID --reason T [--ruling R]`, `retire ID --why T [--ruling R]` | Delete the record and drop `item:ID` from its dependents; an owner-held or owner-priced record needs `--ruling` (Owner gates). `retire --owner-said` is refused with USAGE: the owner's words are never written into a record |
| `migrate [--dry-run] [--to ref\|branch] [--dir D]` | Copies `D/*.md` (default `docs/backlog`, or the configured folder) at the remote's main into a new store as its root commit, with the one-off migration steps (docs/backlog-store.md "Migration"). `--to` defaults to the configured `ref` or `branch` store. REFUSED when the store exists |
| `retarget OLD NEW [--apply]` | Rewrites a moved path across every record's `scope:`, `ref:` and `summary:` lines (Retarget, below). A dry run by default: it prints each record and line it would change and writes nothing; `--apply` writes them all as one store commit |
| `catch-up [--apply PATH...]` | A `main` store only (USAGE otherwise). A dry run by default: lists each uncommitted path under the store folder with its kind (`added`, `modified`, `deleted`, or `not a record`) and the counts, and commits nothing (store.py `MainBackend.pending`). `--apply PATH...` commits exactly the named paths as one commit, the way a write commits (above), with one difference: `MainBackend.commit_paths` passes no HEAD from before it hashed the files, so the compare starts at the HEAD its first attempt finds, and a commit of a named path that another session made between that hashing and that first read of HEAD is overwritten. The dry run may therefore list a path a refused write left (above) or one another session has since committed: read the record with `show`, and compare the file with HEAD, before `--apply`. Its commit has the subject `backlog: catch up N uncommitted record path(s)`. Each path must be an uncommitted record path the dry run lists, or the whole call is USAGE and nothing moves (store.py `catch_up`); outside the PM data worktree it is ERROR (`MainBackend.commit_paths`). It stages nothing else. Tests: `tests/backlog/test_pmdata_commit.py` |
| `set-status ID parked --q Q-nnn`, `unpark ID --ruling R` | Park an open or pulled record on an owner question (a pull is given up; parked records are never offered and take no place in the cap); `unpark` opens it with `resume: R`, which ranks above priority and below a pin |

Exit codes (kitlib/backlog/errors.py): 0 OK; 1 `NOT FOUND:`, `ERROR:`, a RED check; 2 `USAGE:`, `REFUSED:`, or bad arguments. Every write refusal leaves the store untouched. By kind: `Usage` 2, `Refusal` 2, `NotFound` 1, `Failure` 1, except `IndexStale`, whose write is committed and which tools/backlog.py reports as written with a `WARNING:` line, exit 0 ("Stores"); a bad id shape and an unblock of a record that is not blocked are `USAGE:`, an id already taken is `REFUSED:`. `tests/backlog/test_refusal_kinds.py` pins the codes and audits the guard sites by AST.

A record passed over on a scope collision (in `next`, and in a `pull` refused as out of order) names both colliding paths and the holder: `already taken by ID (in flight on BRANCH)` for a live pull, `by ID (session S)` for another session's record, `by ID (offered above)` for one already in the offer (kitlib/backlog/offer.py `next_offer`). A pulled record holds its current `scope:` lines, never its branch's diff, so narrowing them with `set ID --scope P` frees the rest (`tests/backlog/test_pull_holder.py`).

### Retarget

`retarget OLD NEW` follows a moved file or folder through the store (kitlib/backlog/retarget.py `plan_retarget`; `tests/backlog/test_retarget.py`). OLD and NEW are plain repo-relative paths. USAGE: a glob in either, `none` in any case (`NONE` too), a control character (a line break would split a record line), a machine path, OLD equal to NEW, or one under the other (`a` to `a/b`; retarget through a path outside both). Matching is case-sensitive and by whole path components, so OLD `docs/guide` never touches `docs/guidebook.md`.

- `scope:` lines. A member equal to OLD becomes NEW. A member under OLD has that prefix replaced, the trailing `/**` included: with OLD a folder, `OLD/a.md` becomes `NEW/a.md` and `OLD/**` becomes `NEW/**`. A rewritten member the record already holds is dropped, not written twice. Listed as `not rewritten` and left alone: a member that covers OLD from above (`docs/**` or `docs` when OLD is `docs/guide`), since narrowing it is a judgement for `set ID --scope`; and one that matches OLD only when case is ignored (`Docs/Guide/a.md`), which the store's casefolded collision checks treat as the same path but a rename never guesses.
- `ref:` and `summary:` lines. OLD is replaced wherever it stands as a whole path: not preceded by a path character, and followed by the end, a `/` (a path under OLD) or a character that cannot continue a path (a sentence's full stop counts). An OLD with no `/` (`tools`) is replaced only where a `/` follows it; a line where it stands as a bare word is listed as `not rewritten`.
- Nothing else changes: `area`, `files` and the body are left as they are.

The dry run plans against a fresh read and runs the same checks a write does. `--apply` writes every changed record in one store commit, `backlog: retarget OLD -> NEW in N record(s)`; with nothing to change it writes nothing.

## Owner gates

An owner price (`--priority-by owner|pm`), an owner hold (`blocked_on: owner`, `priority: -1`), and closing or retiring such a record take `--ruling R-nnnn`; for a retirement the ruling alone satisfies the owner check and nothing of the owner's is written into the record. A cited id is taken on its word: no write and no `check` reads the rulings ledger, whatever the machine config names (`_check_ruling` in kitlib/backlog/plan.py, `check_store` in kitlib/backlog/check.py). A ruling is refused only for its shape (USAGE), for the id the record already carries as `priority_ruling` (one ruling, one change), for an id the record already spent on a hold release, or, on a price change, for the record's own `hold_ruling`. A `close` citing the record's own live `hold_ruling` is not checked at all (`plan_close`). An out-of-order `pull --ruling` that releases no `priority: -1` records the ruling as `(PM R-nnnn)` after its reason (`plan_pull`). `unpark`'s ruling is checked as a hold release's and sets `resume` (`plan_unpark`).

## Records

The existing record format, unchanged (every record of the first repository ported parses). A header key or value is one line: every write refuses a line break or other control character in one with USAGE, whatever the verb (kitlib/backlog/record.py `render`; `tests/backlog/test_scope_shape.py`); the body is not checked. A tab is let through, since it splits no line and a record that already holds one (a pasted summary) must still take writes; a tab in a scope or files path is still refused when a write adds it, as a new `check` finding, while a tab a scope member already holds is an ordinary character to `next` and the collision test (kitlib/backlog/scope.py `path_shape_error` `tab_ok`). Keys cut in the rewrite are unknown keys: `keys`, `class`, `small_fix_*`, `migrated`, `artefact`, `anchor`, `hold_spent`, `value*`.
