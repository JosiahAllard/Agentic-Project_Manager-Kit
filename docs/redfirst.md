# redfirst

`tools/redfirst.py [-C WORKTREE] --tests FILE[::FILTER] ... [--also FILE ...] [--base REV] [--head REV] [--log-dir DIR]` runs new tests against the pre-change commit and confirms they fail there: red-first evidence with no in-place mutant. `-C` defaults to the current directory; a main checkout is refused. Logic: `kitlib/redfirst` (`verdict.py` pure, `run.py` git and cleanup); the module docstrings hold the full rules. `--tests` and `--also` each take several values and may also be repeated (`--tests A --tests B` is `--tests A B`).

- The test files must be committed at `--head` (default HEAD). They are checked out into a throwaway detached worktree at `--base`, `<main checkout>/<worktrees_dir>/redfirst-<base10>-<pid>`. The default base is the merge-base with `<remote>/<main branch>`. The caller's worktree is only read. A main checkout is refused. It reads no landing lock and does no fetch, and the branch under test need not be pushed (`tests/redfirst/test_run.py`, `Runs.test_red_with_the_landing_lock_held_and_the_head_unpushed`); `new_worktree.py` points here when it refuses a `--base` with no pushed branch.
- `.kit.json` "redfirst".runners picks the runner. The first entry whose `glob` matches the path (case-blind) wins. Kinds:
  - `python`: `python -m unittest` with `PYTHONPATH=<pythonpath>`;
  - `gradle`: `<dir>/gradlew <project>:test --offline --tests <filter>`;
  - `dotnet`: `dotnet test <csproj>` with a trx log.
  
  A runner's `args` are appended. The keys are listed in docs/kit-json.md under "`.kit.json` keys".
- Runners not written (`kitlib/redfirst/run.py`, `runners_for`): the schema default `tests/*test_*.py`, then a python runner `<tools_dir>/*test_*.py` whose `pythonpath` is the tools folder (`"repo".tools_dir`), so a repo that keeps its tests in its tools folder needs no key. That runner imports those tests as top-level modules of the tools folder, so a test that does not import that way reports RED with the ImportError in its reason line. No glob is added when `tools_dir` is `.` or the glob equals one already listed. Written runners are used as they are; no glob is added.
- A `--tests` path no runner takes is refused, exit 2, nothing made (`run.py`, `select` and `no_runner_text`): the refusal lists each glob tried with how many files committed at `--head` it matches, says whether the globs are the written ones or the defaults, and names `"redfirst".runners` as the key to set (`tests/redfirst/test_run.py`, `UnwrittenRunners`).
- One line per selector: RED, GREEN, NONE (no test matched) or ERROR. A python test that does not import against the base is RED, with the final ImportError or ModuleNotFoundError line as its reason. A gradle or dotnet compile error is RED only when it names a copied test file; otherwise it is ERROR.
- Cleanup runs on every exit the process controls, Ctrl-C included:
  - It runs in a child process on its own console.
  - It puts back the base's copy of each `--also` file, then removes the tree with `kitlib.worktree.remove` (the checks and `git_remove` that `worktree_remove.py` uses), never forced.
  - A tree still held after `"redfirst".hold_wait` seconds is left in place, with the `worktree_remove.py` command that removes it.
- Exit codes: 0 every selector RED, 1 any GREEN, 2 usage or refusal (`--help` too), 3 undecided, 4 throwaway left; 6, 8, 10, 11 or 12 when the machine lock refused the run ("The machine lock" below).

## The machine lock

A run whose command is heavy books the machine lock itself, so the caller does not wrap `redfirst.py` in `machine_lock.py run` (`kitlib/redfirst/run.py`: `lock_kind`, `one_lock`, `book_slot`, `locked_run`; tests: `tests/redfirst/test_lock.py`).

- **Which kind.** A runner's `lock` (docs/kit-json.md, `redfirst.runners`) names the kinds-table kind. Without it the kind is that of the first heavy-list entry the runner's command matches (`kitlib.config.heavy_match` over `heavy_programs`: the kit defaults, then the repo's `heavy.programs`): `build` for `gradlew` and for `dotnet test`, none for the python runner. A run with no kind books nothing and runs as before (`run.py`, `default_run`).
- **One booking a run.** The run books once, before the throwaway tree is made, as `<repo name>/redfirst-<base10>` (`kitlib.lock.run.book`; the repo name is `"repo".name`, else the main checkout's folder name), runs every command in the booked run's job, and releases before the cleanup. `--tests` values that need two different kinds are refused, exit 2, with the kind of each; run them in separate calls.
- **No wait limit.** A busy lock queues the run and it waits its turn. Ctrl-C while it waits ends the wait: the lock removes the run's entry, no tree is made, exit 3. A Ctrl-C that arrives inside `kitlib.lock.run.book` before that wait has started is only noted (`run.py`, `Interrupts`, BOOK mode): the run still joins the queue and waits, and ends with exit 3, its slots given back, once it holds them, or at a second Ctrl-C during the wait.
- **Inside a caller's run** (`MACHINE_LOCK_RUN`, as `kitlib.lock.run.nest_check` accepts it):
  - The caller's run holds as many slots as the kind needs, or more: redfirst takes nothing more and its command runs on the caller's cores. The `lock` line says `nested: run <id> already holds what it needs`.
  - The caller's run holds slots of a pool the kind needs, but fewer than it needs: the lock refuses the nested run (`kitlib.lock.run.nest_need`), and redfirst prints `refused: the machine lock: nested run refused: ...; start it outside that run`, makes no tree, runs nothing and exits 2. Run `redfirst.py` outside that run, where it books for itself.
  - The caller's run holds no slot of a pool the kind needs: redfirst books that pool itself.
- **Refusals.** When the lock refuses the run, no tree is made and nothing is run; the log folder, made first, stays. A usage refusal is exit 2: the nested one above, a `lock` kind the kinds table does not have, or a kind that takes a gpu slot of its own while a background run's wrapper (`MACHINE_LOCK_BG`) is an ancestor of the process (`kitlib.lock.run.book`: `a gpu lock inside a background run would pause that run; refused`). The others print `NOT RUN: the machine lock refused the run: <the lock's line>` and `REDFIRST NOT RUN - ...` and exit with the lock's own code (`run.py`, `LOCK_CODES`; `kitlib/lock/store.py`). None of them is 0 or 1, so a refusal never reads as RED or GREEN:
  - 10 (the `require-lock:` lines of `kitlib.lock.run.book` and `acquire`): the kinds table could not be read, or holds a kind whose `cpu` size is past the layout's `agent_cap` (`kitlib.lock.kinds.check_cap`); its run id was taken ("run id ... is taken" for a given id, "no free run id" once every draw was, `kitlib.lock.run.claim_id`) or the lock's store could not be written; the holds or the queue could not be read, or the queue could not be written or its store mutex was not had in time (`kitlib/lock/store.py`, `lock`), before the run had joined the queue. It is the one of these codes `book` gives for what `book_slot` passes, which is no wait limit and no hold.
  - 6 (busy), 8 (the wait ran out), 11 (an owner or game hold leaves too few slots past the wait limit) and 12 (a hold the run names cannot be claimed) are passed through should the lock give them; each needs a wait limit, `no_wait` or a named hold (`kitlib.lock.run.acquire`, `book`). With none of those a hold over the slots parks the run until it clears.
  - Any other failure of the lock is exit 3, a `machine_lock.py stop` of the run while it waits among them: the lock ends that wait with its own code 1, which here would read as GREEN.
- **The run's record.** The booked run ends, before the cleanup, with the code the verdicts give (0, 1 or 3), 130 after Ctrl-C, 1 after an error. A `machine_lock.py stop` of the run ends the command it is running (`kitlib/lock/run.py`, `Slot.wait`; the record ends `cancelled`, 1): the run prints `failed    the machine lock stopped run <id>; its command was ended and gives no verdict`, runs no later selector and counts the stopped one as ERROR. The exit is then what `kitlib.redfirst.verdict.exit_code` gives for the verdicts so far and that ERROR: 4 when the cleanup leaves the tree; else 1 when an earlier selector of the run was GREEN, which is that test's own pass at the base; else 3. It is never 0.
- **Build daemons.** A Gradle daemon the command starts is treated as any run's (docs/gate.md "Build daemons"): `kitlib/lock/run.py` `Slot.stop_daemons` stops it at the release only when `machine_lock.daemons` says so, which the default `gates` does not for a redfirst run, so it runs on unpinned after the release.

Not ported: the pid shield around the test run. Tests: `tests/redfirst`.
